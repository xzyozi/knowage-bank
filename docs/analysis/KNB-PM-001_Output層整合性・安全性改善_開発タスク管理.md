## 1. 現状と方針
Issue同期はMarkdownを生成し、保存前にMarkdown検証、`data/article_sources/issue-<番号>.md`への原本保存、保存後再読込検証、HTML生成・保存後HTML検証、index同期、状態更新を順に行う。`failed` の既存Issueは自動的に再試行しない。IT-OUT-08の再試行承認は、対象・理由・状態遷移を受け付ける公開APIまたはCLIが未実装のため、FEAT-04から分離し、将来の再試行承認ワークフロー機能で扱う。

## 4. #11 / #13 調査記録
`data/article_sources/` に対象Markdown原本は存在せず、`public/articles/` に対象記事HTMLは存在しない。`public/index.html`には対象記事への参照がなく、リポジトリ内に対象処理の実行履歴も確認できなかった。したがって成果物の成功・失敗原因を推測で補わず、`failure_reason`へ調査結果を記録した。状態は`failed`のままとし、再試行は将来の再試行承認ワークフローで対象・理由を記録する公開APIまたはCLIが提供された後に限る。
