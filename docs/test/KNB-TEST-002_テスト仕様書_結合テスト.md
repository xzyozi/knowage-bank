本書は、ADR-001の採用済み方針に従い、IssueからMarkdownを正規入力として原本・HTML・index・状態を連携する契約を検証する。記事入力またはLLM出力としてのJSONを生成・修復するテストは対象外とする。`data/issue_status.json`などの状態管理JSONと`config/category_config.json`などの設定JSONの読込み・保存は対象に含める。

## 1. テスト方針・隔離

- 外部LLM、Deep Research MCP、GitHub APIおよびGit操作はすべてモック化し、ネットワーク接続・秘密情報・実アカウントを使用せずに実行する。
- テンポラリディレクトリとテスト用の状態・設定JSONを使用し、`public/`、`data/`の実運用成果物を変更しない。
- indexは現状通常上書きであり、原子的書込み、保存後検証、失敗時の補償は未保証である。該当ケースは現行の状態記録・呼出し結果までを検証し、未保証の成功原子性を期待値にしない。

## 2. 結合テストケース

| テストID  | テスト対象                 | シナリオ・手順                                                                                            | 期待される結果                                                                                                             |
| :-------- | :------------------------- | :-------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| IT-OUT-01 | Markdown正常系             | モックIssueとMarkdown専用LLM出力を与え、保存前検証、原本保存、HTML保存、保存後検証、index同期を実行する。 | `validate_markdown`成功後に原本とHTMLが保存され、`validate_html`成功、index同期後に状態が成功・`index_synced=true`となる。 |
| IT-OUT-02 | 処理対象なし               | 未処理状態のIssueがないテスト状態で同期を実行する。                                                       | 外部呼出し・成果物保存・状態変更を行わず、対象なしとして正常終了する。                                                     |
| IT-OUT-03 | Markdown検証失敗           | 空入力、未閉鎖コードフェンスまたは危険構文を返すモックを与える。                                          | 原本・HTML・indexを保存せず、Issueを`failed`として失敗理由と時刻を記録する。                                               |
| IT-OUT-04 | 原本保存失敗               | 原本保存処理を例外化する。                                                                                | HTML保存・index同期・成功状態更新へ進まず、失敗Issueと原因を記録する。                                                     |
| IT-OUT-05 | HTML保存後検証失敗         | HTML保存後の`validate_html`が失敗するようモックする。                                                     | HTMLは保存済みであり得るが、index同期・成功状態更新へ進まず、失敗Issueと原因を記録する。補償削除は期待しない。             |
| IT-OUT-06 | index同期失敗              | index生成処理を例外化する。                                                                               | 原本・HTML保存済み後に状態を`failed`として記録し、`index_synced=true`にしない。indexの原子性・補償は未保証として扱う。     |
| IT-OUT-07 | 原本からのオフライン再生成 | 既存の`data/article_sources/issue-<番号>.md`だけを与え、LLM・MCP・GitHub APIを呼ばずHTMLを再生成する。    | 同じMarkdown原本からHTMLを生成・保存し、外部サービスへの接続が発生しない。                                                 |
| IT-OUT-08 | 明示承認後の再試行         | `failed` Issueに対し、承認なしと対象・理由を明示した承認ありの両方を与える。                              | 承認なしでは自動再試行しない。明示承認ありの場合だけ再試行対象となり、その試行結果を状態へ記録する。                       |

## 3. 旧シナリオの履歴

以下はRev.1.0で定義した一般的な同期シナリオである。ADR-001採用後は第2節の契約に読み替える。特に、`failed` Issueを手動で`unprocessed`へ戻すだけで再試行させる運用は採用しない。

| 旧テストID | 旧テスト対象   | 履歴上のシナリオ                           |
| :--------- | :------------- | :----------------------------------------- |
| IT-FL-01   | 一括実行モード | `--run-once`による同期1回実行              |
| IT-FL-02   | 処理対象なし   | 未処理Issueがない場合の終了                |
| IT-FL-03   | リカバリ検証   | `failed` Issueを手動で戻して再処理する想定 |

## 2. 現行契約に基づく結合テスト仕様（2026-08-31）

本節は第1節の旧シナリオを置き換える現行仕様である。記事JSON入力は対象とせず、LLM、MCP、GitHub APIはすべてモック化してネットワーク通信・秘密情報なしで実行する。

| テストID  | シナリオ                           | 期待結果                                                                                 |
| :-------- | :--------------------------------- | :--------------------------------------------------------------------------------------- |
| IT-OUT-01 | 有効なMarkdownを生成する           | 原本保存、HTML保存・検証、index同期後に`processed`と成果物情報を記録する。               |
| IT-OUT-02 | `unprocessed`がない                | 対象なしとして終了し、既存状態を変更しない。                                             |
| IT-OUT-03 | Markdown検証が失敗する             | 原本・HTML・indexを成功成果物として記録せず、`failed`に段階・理由・試行IDを記録する。    |
| IT-OUT-04 | Markdown原本保存が失敗する         | `failed`を記録し、後続のHTML生成・index同期を実行しない。                                |
| IT-OUT-05 | HTML保存後検証が失敗する           | `failed`を記録し、index同期・`processed`更新を実行しない。                               |
| IT-OUT-06 | index同期が失敗する                | `failed`を記録する。indexの原子的書込み・途中成果物の補償は現時点で未保証である。        |
| IT-OUT-07 | 保存済みMarkdown原本から再生成する | LLM・MCP・GitHub APIを呼ばずにHTMLを再生成できる。                                       |
| IT-OUT-08 | 失敗Issueを再試行する              | 成果物と失敗理由を確認し、対象Issueの明示承認後にだけ`unprocessed`へ戻して再試行できる。 |
