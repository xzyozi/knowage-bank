# テスト仕様書（結合テスト仕様）
**Markdown正規入力のOutput同期・失敗処理に関する結合テスト仕様**

| 項目     | 内容         |
| :------- | :----------- |
| 文書番号 | KNB-TEST-002 |
| 版数     | Rev.1.2      |
| 改訂日   | 2026-09-03   |

本書は、ADR-001の採用済み方針に従い、IssueからMarkdownを正規入力として原本・HTML・index・状態を連携する契約を検証する。記事入力またはLLM出力としてのJSONを生成・修復するテストは対象外とする。

## 1. テスト方針・隔離
- 外部LLM、Deep Research MCP、GitHub APIおよびGit操作はすべてモック化し、ネットワーク接続・秘密情報・実アカウントを使用しない。
- テンポラリディレクトリとテスト用の状態JSONを使用し、`public/`、`data/`の実運用成果物を変更しない。
- `mcp`が未導入でも、テスト側が最小モジュールスタブを登録してから同期CLIを動的importし、テスト収集を可能にする。
- index同期処理は原子的書込み、保存後検証、検証失敗時の復元を実装済みとする。Output同期テストではindex同期の戻り値をモックし、同期オーケストレーションと状態記録を検証する。

## 2. 結合テストケース

| テストID  | 状態               | シナリオ                           | 期待結果                                                                                  |
| :-------- | :----------------- | :--------------------------------- | :---------------------------------------------------------------------------------------- |
| IT-OUT-01 | 実装済み・検証待ち | 有効なMarkdownを生成する           | 原本・HTML・indexを保存し、`processed`、成果物名、`index_synced=true`、試行IDを記録する。 |
| IT-OUT-02 | 未実装             | `unprocessed`がない                | 外部呼出し・成果物保存・状態変更を行わず、対象なしとして終了する。                        |
| IT-OUT-03 | 実装済み・検証待ち | Markdown検証が失敗する             | 原本・HTML・indexを保存せず、`failed`に段階・理由・試行IDを記録する。                     |
| IT-OUT-04 | 未実装             | Markdown原本保存が失敗する         | `failed`を記録し、後続のHTML生成・index同期を実行しない。                                 |
| IT-OUT-05 | 実装済み・検証待ち | HTML保存後検証が失敗する           | 原本とHTMLは残し、index同期・`processed`更新を行わず`failed`を記録する。                  |
| IT-OUT-06 | 実装済み・検証待ち | index同期が失敗する                | 原本・HTML成果物を記録し、`failed`、`index_synced=false`、失敗理由を記録する。            |
| IT-OUT-07 | 既存単体テスト     | 保存済みMarkdown原本から再生成する | LLM・MCP・GitHub APIを呼ばずにHTMLを再生成できる。                                        |
| IT-OUT-08 | 未実装             | 失敗Issueを再試行する              | 対象Issue・理由を明示した承認後だけ再試行対象とし、試行結果を記録する。                   |

## 3. テスト実行
統合テストは`pytest --run-integration tests/test_output_sync_integration.py`で実行する。テストは`tmp_path`配下の状態JSON、原本、HTML、indexを使用する。通常のpytest実行では`integration`マーカーによりスキップする。

ローカル環境で`uv run`の依存取得が証明書エラーで停止する場合、依存追加・証明書設定をこのテスト変更へ含めない。依存解決後に同じコマンドとlint・型検査を実行する。
